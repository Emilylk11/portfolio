Experimentation &
Revenue Attribution

Building a testing program on a stack that fights you, and fixing the measurement underneath it first.

Client
DTC Supplement Brand
Role
CRO & Growth Manager
Stack
VWO · GA4 · GTM · Apps Script
Scope
Program Ownership
Problem

Tests broke silently, and the data was wrong anyway

Landing pages ran on WordPress and Elementor, checkout on a separate platform. Elementor hydrates the DOM late and injects its own CSS over yours, so tests looked fine in preview and did nothing live. Nothing was reusable, so every test started from scratch. Underneath that, revenue numbers from the ad platform and the checkout never matched.

Framework

Five problems, solved once

Style bleed

Namespaced scoping

Every variant adds a versioned body class and prefixes its CSS with it, so styling can't leak into control traffic.

Silent failure

Polling for late DOM

The target element often isn't there when the campaign fires. Variants poll with a retry cap. This caused more dead tests than anything else.

Wrong target

Content-matched targeting

These pages carry several hidden H1s from mobile menus. Targeting matches on text, then checks the element actually renders.

Broken attribution

Separate CTA classes

Reusing the page's CTA class on an injected button could rewrite affiliate transaction IDs. Injected CTAs get their own.

Double counting

Versioned event keys

dataLayer events fire against versioned session keys, so iterating doesn't double-count or inherit stale state.

All ES5-strict, because the testing platform's parser rejects anything newer. That's not in any documentation I could find.

Measurement

Reading revenue the tool couldn't see

Some high-traffic promo pages ran checkout on a different domain, so the testing platform couldn't see the transaction at all. We were reading those tests on click-through, which isn't the same thing.

I wired the platform's GA4 connection to stamp variant assignment onto the session, then registered custom campaign and variation dimensions. Parameter names had to be confirmed in DebugView after going live, since the integration doesn't fire in preview. That threw me for a while before I worked out it was expected.

Reconciliation

Spend the reporting had lost

I built a reconciliation tool in Apps Script to line up ad revenue against checkout revenue. What came out wasn't a rounding error: a meaningful chunk of paid spend on one product line was routing to a checkout the reporting stack wasn't attributing at all. The channel looked like it was underperforming. It wasn't.

Diagnosis

The 0% mobile conversion rate

A funnel showed 0% mobile conversion and everyone's first instinct, mine included, was the landing page. I segmented by device, browser and channel before touching the design. It was two things stacked: the checkout wasn't rendering properly on mobile, and Safari's tracking prevention was breaking cross-device attribution. A page test would have fixed neither and come back null.
